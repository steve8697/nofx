## 🟠 错误2：决策流程违反"疑惑优先"原则

### 问题分析

**当前问题**：
- 提示词说"直接输出 wait"，但AI仍然继续执行后续步骤
- 没有明确的"跳过"指令

### 修复方案

#### 方案A：提示词强化（推荐）

在 `prompts/adaptive.txt` 的"第 0 步：疑惑检查"部分，修改为：

```markdown
## 第 0 步：疑惑检查
**在所有分析之前，先问自己：我对当前市场有清晰判断吗？**

⚠️ **关键执行规则**：
- 若感到困惑、矛盾、不确定 → **立即停止所有后续分析，直接输出 wait 决策**
- **禁止**：选择 wait 后继续执行第1-8步
- **必须**：在思维链中明确说明"第0步选择wait，跳过所有后续步骤"
- 若完全清晰 → 继续后续步骤

**示例正确输出**：
```
第0步：疑惑检查
- 对当前市场缺乏清晰判断 → 直接选择 wait
- ⚠️ 根据疑惑优先原则，跳过第1-8步所有后续分析
- 最终决策：wait
```

**示例错误输出（禁止）**：
```
第0步：疑惑检查 → 选择 wait
第1步：冷却期检查...
第2步：连续亏损检查...
（继续执行后续步骤）❌ 这是错误的！
```
```

#### 方案B：代码层面验证（可选）

在 `decision/validator.go` 中添加验证逻辑：

```go
// validateDecisionFlow 验证决策流程是否符合"疑惑优先"原则
func validateDecisionFlow(cotTrace string, decisions []Decision) error {
    // 检查思维链中是否在第0步选择了wait
    if strings.Contains(cotTrace, "第0步") && strings.Contains(cotTrace, "wait") {
        // 如果第0步选择wait，检查是否继续执行了后续步骤
        hasStep1 := strings.Contains(cotTrace, "第1步") || strings.Contains(cotTrace, "冷却期")
        hasStep2 := strings.Contains(cotTrace, "第2步") || strings.Contains(cotTrace, "连续亏损")
        hasStep3 := strings.Contains(cotTrace, "第3步") || strings.Contains(cotTrace, "夏普")
        
        if hasStep1 || hasStep2 || hasStep3 {
            return fmt.Errorf("违反疑惑优先原则：第0步选择wait后仍继续执行后续步骤")
        }
    }
    return nil
}
```

**实施建议**：
1. **立即实施**：方案A（提示词强化）
2. **后续优化**：方案B（代码验证）- 可作为警告日志，不强制拒绝

## 🟡 错误3：BTC整数关口检查不够严谨

### 问题分析

**当前问题**：
- 提示词提到"整数关口±2%"，但没有要求明确计算
- AI只是模糊地说"处于整数关口附近"，没有具体数值

### 修复方案

#### 提示词改进

在 `prompts/adaptive.txt` 的"第 5 步：BTC 状态确认"部分，添加：

```markdown
### 特殊情况检查（必须明确计算）

⚠️ **整数关口检查（强制计算）**：
1. 识别最近的整数关口（如 100,000 / 95,000 / 90,000）
2. **必须计算**：距离百分比 = |当前价格 - 整数关口| / 整数关口 × 100%
3. **判断标准**：
   - 距离 ≤ 2% → 高度不确定，必须 wait
   - 距离 > 2% → 可以继续分析，但需在思维链中说明计算结果

**示例**：
```
BTC价格：103635.50
整数关口：100,000
距离：103635.50 - 100000 = 3635.50
距离百分比：(3635.50 / 100000) × 100% = 3.64%
判断：3.64% > 2%，不触发整数关口限制 ✅
```

⚠️ **禁止**：只说"处于整数关口附近"而不计算具体百分比
```

#### 代码层面增强（可选）

在 `decision/engine.go` 的 `buildUserPrompt` 中，为BTC添加整数关口提示：

```go
// 在BTC市场信息部分添加
if btcData, hasBTC := ctx.MarketDataMap["BTCUSDT"]; hasBTC {
    // 计算最近的整数关口
    price := btcData.CurrentPrice
    nearestRound := math.Round(price / 10000) * 10000 // 最近的万位整数
    distance := math.Abs(price - nearestRound)
    distancePct := (distance / nearestRound) * 100
    
    sb.WriteString(fmt.Sprintf("BTC: %.2f (1h: %+.2f%%, 4h: %+.2f%%) | MACD: %.4f | RSI: %.2f\n",
        btcData.CurrentPrice, btcData.PriceChange1h, btcData.PriceChange4h,
        btcData.CurrentMACD, btcData.CurrentRSI7))
    
    if distancePct <= 2.0 {
        sb.WriteString(fmt.Sprintf("⚠️ **BTC整数关口警告：距离%.0f仅%.2f%%（≤2%%），高度不确定，建议wait**\n\n",
            nearestRound, distancePct))
    } else {
        sb.WriteString(fmt.Sprintf("💡 BTC整数关口：%.0f，当前距离%.2f%%（>2%%）\n\n",
            nearestRound, distancePct))
    }
}
```

**实施建议**：
1. **立即实施**：提示词改进
2. **后续优化**：代码层面自动计算并提示

## 🟡 错误4：多空确认清单评估不完整

### 问题分析

**当前问题**：
- 提示词要求填写8项清单，但AI只泛泛而谈
- 没有针对具体币种进行完整评估

### 修复方案

#### 提示词强化

在 `prompts/adaptive.txt` 的"第 6 步：多空确认清单"部分，修改为：

```markdown
## 第 6 步：多空确认清单（V5.5.1 新增）

⚠️ **强制要求**：
1. **必须**针对至少1-2个最有潜力的币种填写完整的8项清单
2. **即使最终选择wait**，也要说明为什么没有币种满足5/8项要求
3. **禁止**只说"大多数币种处于震荡"而不填写具体清单

### 执行步骤

**步骤1**：从候选币种中筛选1-2个最有潜力的币种
**步骤2**：对每个币种填写完整的8项清单表格
**步骤3**：计算一致性（必须≥5/8才能开仓）
**步骤4**：如果所有币种都<5/8，明确说明原因并选择wait

### 示例格式（必须遵循）

```
第6步：多空确认清单评估

**币种1：SOLUSDT（做多评估）**

| 指标 | 做多条件 | 当前状态 | 一致性 |
|------|---------|---------|--------|
| MACD | >0（多头） | 0.151（多头） | ✅ |
| 价格 vs EMA20 | 价格 > EMA20 | 161.73 > 161.80 | ❌ |
| RSI | <35或35-50 | 50.59（中性） | ✅ |
| BuySellRatio | >0.7或>0.55 | 0.52（不足） | ❌ |
| 成交量 | >1.5x均量 | 0.37x（萎缩） | ❌ |
| BTC 状态 | 多头或中性 | 不明确 | ❌ |
| 资金费率 | <0或-0.01~0.01 | 0.000063（正常） | ✅ |
| OI 持仓量 | 变化>+5% | 无数据 | ⚪ |

**一致性：3/8 < 5/8 → 不满足开仓条件**

**结论**：SOLUSDT虽然MACD和RSI支持做多，但价格未突破EMA20、成交量萎缩、BTC状态不明确，一致性不足，选择wait。
```

⚠️ **禁止输出**：
- "大多数币种处于震荡"（没有具体分析）
- "无明显突破"（没有填写清单）
- "技术指标矛盾"（没有说明哪些指标矛盾）
```

#### 代码层面提示增强（可选）

在 `decision/engine.go` 的 `buildUserPrompt` 中，添加提示：

```go
sb.WriteString(fmt.Sprintf("## 候选币种 (%d个)\n\n", len(ctx.MarketDataMap)))

```

**实施建议**：
1. **立即实施**：提示词强化（添加强制要求和示例格式）
