## 🔍 主要原因分析

### 1. **零号原则：疑惑优先（最高优先级）**

系统设计了一个非常保守的"零号原则"：

```12:56:prompts/adaptive.txt
# 零号原则：疑惑优先（最高优先级）

⚠️ **当你不确定时，默认选择 wait**

这是最高优先级原则，覆盖所有其他规则：

- **有任何疑虑** → 选 wait（勿尝试"勉强开仓"）
- **完全确定**（信心 ≥85 且无任何犹豫）→ 才开仓
- **不确定是否违反某条款** = 视为违反 → 选 wait
- **宁可错过机会，不做模糊决策**
```

**影响**：AI 在不确定时会直接选择 wait，而不是尝试开仓。

### 2. **开仓条件极其严格**

#### 2.1 信心度要求高

- **正常情况**：信心度 ≥85 才能开仓
- **夏普比率在 -0.5~0 区间**：只做信心度 >90 的交易
- **突破追单**：信心度 ≥80（但还需要其他条件）

### 4. **系统设计理念**

系统的核心目标是**最大化夏普比率**，而不是最大化交易次数：

```1:18:prompts/adaptive.txt
你是专业加密货币交易AI，在合约市场自主交易。

# 核心目标

最大化夏普比率（Sharpe Ratio）

夏普比率 = 平均收益 / 收益波动率

这意味着：
- 高质量交易（高胜率、大盈亏比）→ 提升夏普
- 稳定收益、控制回撤 → 提升夏普
- 耐心持仓、让利润奔跑 → 提升夏普
- 频繁交易、小盈小亏 → 增加波动，严重降低夏普
- 过度交易、手续费损耗 → 直接亏损
- 过早平仓、频繁进出 → 错失大行情

关键认知: 系统每10分钟扫描一次，但不意味着每次都要交易！
大多数时候应为 `wait` 或 `hold`，只在极佳机会时才开仓。
```

## 💡 为什么这样设计？

### 优点

1. **风险控制严格**：避免频繁交易导致的亏损
2. **质量优先**：只做高质量交易，提高胜率
3. **保护资金**：避免在市场不确定时冒险

### 缺点

1. **交易机会少**：可能错过一些中等质量的机会
2. **资金利用率低**：大部分时间资金闲置
3. **学习数据少**：交易次数少，AI 学习样本不足

## 🔧 如何调整？

### 方案 1：降低开仓门槛（谨慎）

如果希望增加交易频率，可以：

1. **降低信心度要求**：从 85 降至 80
2. **降低一致性要求**：从 5/8（62.5%）降至 4/8（50%）
3. **放宽 BTC 整数关口限制**：从 2% 放宽至 3%
4. **降低风险回报比**：从 1:3 降至 1:2

⚠️ **警告**：这些调整会增加风险，可能导致更多亏损。

### 方案 2：使用更激进的提示词模板

系统支持多个提示词模板：
- `adaptive.txt`：当前使用的保守模板
- `adaptive_relaxed.txt`：更宽松的模板（信心度从 85 降至 80）

### 方案 3：调整系统参数

在配置文件中调整：
- `ScanInterval`：扫描间隔（当前 10 分钟）
- `MaxDailyLoss`：最大日亏损限制
- `MaxDrawdown`：最大回撤限制

## 📝 结论

**交易稀少是系统设计的预期行为**，目的是：

1. ✅ **保护资金**：避免在市场不确定时冒险
2. ✅ **提高质量**：只做高质量交易，提高胜率
3. ✅ **最大化夏普比率**：通过减少低质量交易来提升风险调整后收益

如果希望增加交易频率，需要：
- ⚠️ 接受更高的风险
- ⚠️ 可能降低整体胜率
- ⚠️ 需要仔细测试和监控
