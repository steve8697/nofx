# CoinGecko API 调用频率分析

## 📊 当前情况分析

### 币种数量
- **配置币种**: 37个（从 `config.json` 的 `default_coins`）
- **实际分析币种**: 根据持仓数量动态调整
  - 无持仓时：最多30个候选币种
  - 持仓1个：最多25个候选币种
  - 持仓2个：最多20个候选币种
  - 持仓3+个：最多15个候选币种

### 每次决策周期的调用次数

**当前实现**:
- 每个币种调用 `getCoinGeckoData()`: **1次**（简单价格查询）
- 每个币种调用 `getCoinGeckoMarketCapRank()`: **1次**（获取排名，可选）

**最坏情况**:
- 无持仓 + 30个候选币种 = 30个币种
- 每个币种2次调用 = **60次调用/周期**

### 决策周期频率

- **默认**: 每3分钟一次（`scan_interval_minutes = 3`）
- **最快**: 每3分钟一次（最小限制）

### 每分钟调用次数计算

**最坏情况**:
- 60次调用 / 3分钟 = **20次/分钟** ✅ 在限制内

**实际情况**:
- 市值排名调用是可选的，失败会跳过
- 通常每个币种只调用1次（简单价格查询）
- 30次调用 / 3分钟 = **10次/分钟** ✅ 安全

**但需要注意**:
- 如果有多个trader同时运行，调用次数会叠加
- 如果币种数量增加，可能超过限制

---

## ⚠️ 潜在风险

### 1. 多Trader场景
如果有多个trader同时运行：
- 2个trader: 20次/分钟 × 2 = **40次/分钟** ❌ 超过限制
- 3个trader: 20次/分钟 × 3 = **60次/分钟** ❌ 严重超限

### 2. 币种数量增加
如果币种数量增加到50+：
- 50个币种 × 2次 = 100次/周期
- 100次 / 3分钟 = **33次/分钟** ❌ 超过限制

### 3. 决策周期缩短
如果 `scan_interval_minutes` 设置为更短：
- 1分钟周期: 30次/分钟 = **30次/分钟** ⚠️ 接近限制

---

## ✅ 优化方案

### 方案1: 批量查询（推荐）

CoinGecko API支持批量查询多个币种，一次调用可以获取多个币种的数据。

**优化前**:
```go
// 每个币种单独调用
for symbol := range symbolSet {
    coinGeckoData, _ := getCoinGeckoData(symbol)  // 1次API调用
}
// 30个币种 = 30次调用
```

**优化后**:
```go
// 批量查询所有币种
coinGeckoDataMap, _ := getCoinGeckoDataBatch(symbols)  // 1次API调用
// 30个币种 = 1次调用
```

**效果**: 从30次调用减少到1次调用，**减少97%的API调用**！

### 方案2: 添加缓存

缓存CoinGecko数据，减少重复调用。

**缓存策略**:
- 缓存时间：5-10分钟（市值排名变化不频繁）
- 缓存键：币种符号
- 缓存失效：时间到期或手动清除

**效果**: 如果多个trader使用相同币种，可以共享缓存。

### 方案3: 速率限制保护

添加速率限制器，确保不超过30次/分钟。

**实现**:
- 使用令牌桶算法
- 限制：30次/分钟
- 超限时：等待或跳过CoinGecko数据

### 方案4: 选择性调用

只对主要币种获取完整数据（包括排名）。

**策略**:
- 市值排名：只对Top 20币种获取
- 其他币种：只获取价格和24h变化
